# Use Django as the primary framework

## Context and Problem Statement

The thesis supervisor requested the new implementation should be done in Python. As the resulting application is still web-based, a good Python web framework should be selected to speed up the development and avoid common mistakes.

## Considered Options

* [Django](https://www.djangoproject.com) - batteries-included, provides tools for most of the common tasks
* [Flask](https://flask.palletsprojects.com) - lightweight, relatively non-opionionated, good for simple apps
* [FastAPI](https://fastapi.tiangolo.com) - API framework, would require building a SPA

## Decision Outcome

Chosen option: Django, because:

* Suits the data-model heavy orientation of the application (out of box ORM, automatic admin interface)
* Forces good architecture, but does not prevent execution of strangler fig migration.
* Large ecosystem of third party extensions, which may be useful in development (API, auth, ...)
* The author is moderately familiar with it.

### Consequences

Good:

* Expected speed up of development due to the batteries-included philosophy of the framework.
* Less time spent learning new tech stack.
* Secure defaults for common use out of box.
* Autogenerated admin interface may help with database during migration.

Bad:

* Django's opinionated architecture may make unusual requirements or framework replacements more difficult.
* Framework conventions and “magic” can increase the learning curve for future developers unfamiliar with Django.
